# 🧪 Гайд: Slave-симулятор в mbSCADA

> Актуально для **v1.3.0**. Slave-симулятор — вкладка приложения, где mbSCADA сама отвечает как Modbus-устройство: любые мастера (и сама mbSCADA) могут читать и писать её регистры. Обе стороны «кабеля» — в одном окне.

---

## 1. Зачем это нужно

Классическая проблема автоматизации: чтобы отладить верхний уровень (таблицы, правила аварий, SCADA-схему, вычисляемые тэги), нужен либо реальный контроллер, либо внешний симулятор. Slave-симулятор закрывает это прямо в приложении:

- **Отладка проекта без железа.** Подняли slave, направили на него свои опросы — таблицы оживают, правила срабатывают, виджеты шевелятся.
- **Имитация и мастера, и slave.** На экране одновременно видны разнородные данные вперемешку — real, int, uint, hex, биты — и их можно **вводить вручную**: с одной стороны вы «устройство», которое раздаёт значения, с другой — «оператор», который их читает и пишет.
- **Эмуляция конкретного устройства.** Импортируйте карту регистров из `.mbp` (Modbus Poll), поправьте типы в один клик — и приложение поведёт себя как это устройство.
- **Проверка сторонних мастеров.** Modbus Poll, скрипты, HMI-пакеты — наведите их на симулятор и сравните поведение.
- **Обучение и демонстрация.** Безопасная песочница: порт виртуальный, сломать ничего нельзя.

## 2. Быстрый старт за две минуты

1. Откройте вкладку **«Slave-симулятор»** в верхней панели.
2. Оставьте значения по умолчанию: **Порт 10502**, **Slave ID 1**, **Кадры — Modbus TCP**. Нажмите **▶ Запустить slave**. Статус покажет `✓ 0.0.0.0:10502 · Slave 1 · TCP · клиентов: 0`.
3. Перейдите на вкладку «Соединения» и добавьте соединение: тип **TCP**, хост **127.0.0.1**, порт **10502**, Slave ID **1**.
4. Добавьте опрос: функция **03 Holding**, старт **0**, количество **16**, тип **u16**, период 500–1000 мс.
5. Нажмите **▶ Старт** (запуск движка). В таблице появятся значения — пока нули.
6. Вернитесь на вкладку Slave-симулятора, выберите **Автогенерация → синус**, Амплитуда 100, База 50. Каждые ~0,3 с диапазон оживёт.
7. Смотрите на таблицу опроса: значения «дышат». Кликните по строке таблицы мастера — окно записи — введите новое значение. Оно попадёт в slave, и вы увидите его в сетке симулятора.

Всё: мастер и slave работают в петле на одной машине.

## 3. Вкладка «Slave-симулятор»: разбор всех элементов

![Slave-симулятор](img/slave.png)

### 3.1 Панель запуска

| Элемент | Что делает |
|---|---|
| **Порт** (1–65535, по умолчанию 10502) | TCP-порт, на котором slave слушает подключения. Слушается адрес `0.0.0.0` — устройство доступно и с локальной машины, и по сети. |
| **Slave ID** (0–247) | Адрес устройства. Используется как преднастроенное/справочное значение; сам slave отвечает на запросы с любым адресом unit — адрес из запроса возвращается в ответе. |
| **Кадры** | `Modbus TCP (MBAP)` — стандартные TCP-кадры; `RTU over TCP` — те же RTU-кадры с CRC16, но поверх TCP (так работают многие шлюзы и «серые» устройства); `Serial RTU (COM/RS-485)` — **настоящая последовательная линия** через USB-RS485 адаптер (v1.4). |
| **▶ Запустить slave** | Поднимает сервер. Если порт/линия заняты — сообщение об ошибке в строке статуса/футере. Повторный клик ничего не ломает (идемпотентно). |
| **■ Остановить** | Останавливает slave и освобождает порт/линию. |
| **Статус** | `✓ адрес · Slave N · TCP/RTU/TCP · клиентов: N` — число открытых TCP-подключений (два мастера одновременно → `клиентов: 2`). Для serial — `✓ COM3 @ 9600 8E1 · Slave N · Serial RTU`. |

Параметры линии **Serial RTU** появляются под панелью запуска, когда выбраны такие кадры:

| Элемент | Что делает |
|---|---|
| **COM-порт** | Список портов ОС (⟳ Обновить — перечитать). USB-RS485 адаптер обычно виден как `COM3 — USB Serial` или `/dev/ttyUSB0`. |
| **Скорость** | 1200…115200 бод; классика Modbus — 9600. |
| **Чётность** | `E` (чётность, по умолчанию RTU), `N` (без), `O` (нечётность). Должна совпадать с мастером на линии. |
| **Данные / Стоп-биты** | Обычно 8 и 1 (`8E1` целиком). Настраивайте так же, как у опрашивающего мастера. |

Линия устойчива к мусору: кадр с битым CRC отбрасывается, несуществующий функциональный код пропускается побайтно, «висящий» обрывок кадра стирается по тишине на линии (300 мс) — глюк мастера не кладёт slave, устройство продолжает отвечать.

### 3.2 Область и диапазон

Параметры **Область / Адрес / Кол-во** задают, какой кусок памяти устройства показывать в сетке ниже и куда пишет автогенерация:

- **03 Holding** — регистры чтение/запись (самая ходовая область);
- **04 Input** — регистры только для чтения (измерения);
- **01 Coils** — биты чтение/запись;
- **02 Discrete** — биты только для чтения.

Адрес — 0…65535, Кол-во — 1…200 ячеек. Каждая область — отдельный массив на 65 536 ячеек, так что можно показывать и редактировать любой срез без конфликтов с другими областями.

### 3.3 Вид (тип данных сетки)

Селектор **«Вид»** задаёт, как интерпретировать регистры в сетке симулятора:

| Вид | Регистров на значение | Что видно |
|---|---|---|
| uint16 | 1 | 0…65535 |
| int16 | 1 | −32768…32767 (допкод) |
| hex16 | 1 | биты регистра |
| u16 (swap) | 1 | байты в регистре переставлены |
| uint32 / int32 | 2 | 32-битное целое из двух регистров |
| float CDAB / float ABCD | 2 | float32 с разным порядком слов |

Число строк сетки = **Кол-во ÷ регистров на значение**: ввели 16 ячеек с видом `float CDAB` — получите 8 строк float, каждая занимает два адреса (0–1, 2–3, …).

### 3.4 Автогенерация

Чтобы диапазон «жил» без ручного ввода:

- **выкл / синус / пила / шум** — форма сигнала;
- **Ампл.** — размах (для шума — верхняя граница случайных значений);
- **База** — средний уровень, вокруг которого гуляет сигнал;
- **Период, с** — длительность одного цикла синуса/пилы.

Генератор пишет в выбранную область/диапазон каждые ~0,3 с. Для битовых областей (Coils/Discrete) значение превращается в 0/1 по порогу 50 % от размаха. Автогенерация работает, пока slave запущен, — вкладку можно свернуть, мастера продолжат получать живые значения.

### 3.5 Таблица регистров

Три колонки: **Адрес | Значение | Регистры**.

- **Значение** — редактируемое поле в выбранном «Виде». Ввели число (или `0x1F` для hex) и нажали Enter / увели фокус — значение пакуется в регистры по правилам типа (float → два слова с учётом порядка, int16 → допкод) и сразу попадает в модель устройства. Внешние мастера увидят новое значение при следующем опросе.
- **Регистры** — сырые hex-биты тех же данных: удобно сверять порядок слов, ловить расхождения float-порядков и сверяться с документацией на реальное устройство.
- Для **Coils/Discrete** вместо поля ввода — чекбоксы.
- Пока курсор стоит в поле ввода, фоновое обновление не перезапишет значение — можно спокойно редактировать при активном опросе.

## 4. Как подключить мастер

### Вариант А. Сама mbSCADA (петля на одной машине)

1. Соединение: тип **TCP**, хост **127.0.0.1**, порт **10502** (или ваш), Slave ID — адрес устройства.
2. Опросы — как обычно: функция, старт, количество, тип, период.
3. Slave ID в опросе можно не задавать — он унаследует адрес из соединения (если не переопределён).

### Вариант Б. Modbus Poll / другой мастер на этой же машине

Направьте его на `127.0.0.1:10502`, unit = адрес устройства, режим — Modbus TCP (или RTU over TCP, если выбрали такие кадры). Удобно для сравнительного тестирования: mbSCADA и Modbus Poll смотрят на одно устройство одновременно (`клиентов: 2`).

### Вариант В. С другой машины по сети

Slave слушает `0.0.0.0`, поэтому с другого компьютера (или телефона с Modbus-приложением) подключайтесь к **IP машины, где запущена mbSCADA**, порт — ваш. Проверьте:

- брандмауэр Windows при первом запуске спросит про сетевой доступ — разрешите;
- в некоторых сборках Windows порт может быть закрыт для внешних интерфейсов — добавьте правило для порта 10502;
- кадры у мастера должны совпадать с выбранными на вкладке (TCP ≠ RTU over TCP).

### Шпаргалка параметров для мастера

| Параметр мастера | Значение |
|---|---|
| Режим | Modbus TCP или RTU over TCP — как на вкладке |
| IP | `127.0.0.1` (та же машина) или IP компьютера по сети |
| Порт | из вкладки (по умолчанию 10502) |
| Unit / Slave ID | любой (не фильтруется); обычно 1 |
| Функции | 01, 02, 03, 04, 05, 06, 15, 16, 22, 23 |

## 5. Разнородные данные: real / int / uint вперемешку

Главная идея: **тип данных — свойство опроса**, и у каждого опроса есть быстрый селектор типа прямо на карточке таблицы (аналог «Number Type» в Modbus Poll). После импорта `.mbp` достаточно пройтись по опросам и выставить тип одним кликом.

Полный список типов: **u16, i16, hex16, bin16, ascii16, u16 swp, u32, i32, hex32, f32 ABCD / CDAB / BADC / DCBA, u64, i64, f64**.

Что это даёт:

- **Число строк считается правильно.** Строк в таблице = Кол-во ÷ регистров на значение: float32/u32 — два регистра на значение, f64/u64 — четыре. Десять float при qty=20 — ровно десять строк, адреса 0, 2, 4…
- **Типизированные окна записи.** Клик по строке таблицы мастера — окно ввода. Значение подставляется в удобном виде: float — инженерное число (`12.5`), hex/bin — битовый шаблон (`0x1F4`), ascii16 — два символа. После правки значение пакуется в регистры по типу: float → два слова с нужным порядком, i16 → допкод, hex/bin принимаются с префиксами `0x…`/`0b…`. Запись уходит как FC06 (одно слово) или FC16 (несколько), биты — FC05.
- **Область 04 Input — только чтение.** При попытке записи приложение вежливо откажет и объяснит: input-регистры по стандарту пишет устройство, а не мастер.
- **Смешанные данные в одном проекте.** Опрос №1 — float CDAB (температуры), опрос №2 — u16 (статусы), опрос №3 — i32 (счётчики): все три карточки живут на одном экране одновременно, каждая со своим типом, отображением и правилами аварий.

**Про `.mbp` и типы.** Из файла Modbus Poll надёжно подтягиваются адреса, имена, функции и количество точек. Тип числа (Number Type) в бинарнике `.mbp` хранится не по спецификации и зависит от версии — поэтому тип выставляется селектором в один клик, а не «угадывается» при импорте. Остальное (соединения, опросы, структуру) импорт делает сам.

## 6. Отображение в ячейке: dec → hex → bin

Отображение — отдельная от типа данных настройка: тип определяет, **как интерпретировать регистры**, отображение — **как показать значение человеку**.

- **ПКМ по значению** в таблице мастера — цикл **dec → hex → bin** для этой конкретной ячейки.
- **Селектор на карточке опроса** (dec/hex/bin) — формат по умолчанию для всех ячеек опроса.
- **hex/bin показывают сырые биты регистров значения** независимо от типа: float 12.5 в hex будет выглядеть как `0x41480000` — так удобно сверяться с документацией устройства.
- Настройки отображения **сохраняются в проекте** вместе с остальными: открыли проект — получили привычную картинку.

## 7. Готовые сценарии

### А. Отладка правил аварий без железа
1. Slave: 03 Holding, адрес 0, кол-во 16, автогенерация **синус**, База 150, Амплитуда 100.
2. Опрос 03 Holding @0×16 u16, период 500 мс.
3. Правило: «значение > 220 → авария». На пиках синусоиды авария сработает, в панели аварий появится карточка, история запишет длительность. Звук, ACK, переход к строке — всё как с реальным устройством.

### Б. Эмуляция устройства по карте из .mbp
1. Импортируйте `.mbp` (Импорт → проект Modbus Poll).
2. Пройдитесь по опросам, выставьте типы селектором (float CDAB для температур, u16 для статусов…).
3. Поднимите slave на тех же областях/адресах, введите реальные значения вручную — проект «оживил» документированное устройство.

### В. Оживление SCADA-схемы и окна параметров
Автогенерация (пила на гейдж, шум на лампы, синус на график мимики) + watch-окно с 4–6 карточками — наглядное демо и проверка компоновки схемы до выезда на объект.

### Г. Два мастера на одном slave
mbSCADA + Modbus Poll одновременно: счётчик клиентов покажет 2; запись из одного мастера тут же видна в другом — идеальный способ отследить «кто перезаписывает регистр».

### Д. Проверка RTU over TCP
Кадры **RTU over TCP** — те же RTU-кадры с CRC16, но по TCP. Мастера с режимом «RTU over TCP / Modbus TCP with RTU framing» подключаются так же, а приложение честно парсит CRC — если мастер шлёт битые кадры, соединение просто не сложится.

### Е. Эмуляция устройства на физической шине RS-485 (v1.4)
Классика полевых работ: мастер (контроллер, HMI, шлюз) опрашивает устройство по RS-485, а вам нужно отработать его логику без самого устройства.

1. Понадобится любой USB-RS485 адаптер. Подключите его к шину **A/B** там, где стоит эмулируемое устройство: **реальное устройство с тем же Slave ID на линии надо отключить** — два слейва с одним адресом конфликтуют.
2. Вкладка «Slave-симулятор» → Кадры **Serial RTU (COM/RS-485)** → выберите порт, скорость/чётность как у мастера на линии (например `9600 8E1`) → **▶ Запустить slave**.
3. Настройте области/адреса под карту реального устройства (или импортируйте `.mbp` этого устройства) и вводите значения вручную либо автогенератором.
4. Мастер на линии «не заметит подмены»: опрашивает — наше устройство отвечает, пишет — регистры меняются. Логика, аварийные уставки и реакции мастера отрабатываются на реальной линии.

Зеркальный вариант: если «разъём слейва» есть у вашего ПК-мастера, mbSCADA сама умеет опрашивать физические RTU-устройства — соединение типа **RTU** с COM-портом (адаптер в разъём слейва устройства). Так проверяются обе стороны кабеля: и мастер приложения → реальный слейв, и сторонний мастер → симулятор приложения.

## 8. Что поддерживает slave (функции Modbus)

| FC | Операция | Область | Комментарий |
|---|---|---|---|
| 01 | Read Coils | Coils | чтение битов |
| 02 | Read Discrete Inputs | Discrete | чтение битов |
| 03 | Read Holding Registers | Holding | чтение регистров |
| 04 | Read Input Registers | Input | чтение регистров |
| 05 | Write Single Coil | Coils | один бит |
| 06 | Write Single Register | Holding | один регистр |
| 15 (0x0F) | Write Multiple Coils | Coils | пачка битов |
| 16 (0x10) | Write Multiple Registers | Holding | пачка регистров |
| 22 (0x16) | Mask Write Register | Holding | AND/OR-маска |
| 23 (0x17) | Read/Write Multiple Registers | Holding | атомарно чтение+запись |

Вне диапазона или неизвестная функция → стандартный Modbus-эксепшен (illegal address / illegal function), мастера видят честный протокол.

## 9. Что сохраняется в проекте

В файле проекта (`.json`) вместе с соединениями, опросами, правилами и виджетами хранится и конфигурация slave-вкладки: **порт, Slave ID, кадры, область, адрес, количество, вид, режим и параметры автогенерации** (амплитуда, база, период), а также форматы отображения ячеек. Передали проект коллеге — у него симулятор поднимется в той же конфигурации.

Сами значения регистров не сохраняются — это «живое» состояние устройства; после запуска slave начинается с нулей (или заполняется автогенератором).

## 10. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| «порт 10502 занять не удалось» | Порт занят другим slave-процессом/программой | Смените порт на вкладке или закройте того, кто держит порт |
| Мастер показывает «нет связи» | Не совпадают порт/кадры, или блокирует брандмауэр | Проверьте host:port, тип кадров (TCP vs RTU over TCP), правило брандмауэра |
| Соединение есть, но значения «странные» | Не тот порядок слов у float | Попробуйте другой float-порядок (CDAB ↔ ABCD) — смотрите сырые регистры в колонке «Регистры» |
| Строк в таблице вдвое меньше ожидаемого | Это нормально: float/32-бит занимают 2 регистра на значение | Увеличьте «Кол-во» вдвое или выберите 16-битный вид |
| Запись не проходит | Область 04 Input только для чтения | Пишите в 03 Holding / 01 Coils — по стандарту Modbus |
| Автогенерация «не видна» в мастере | Разные области/адреса у генератора и опроса | Сведите область/адрес/кол-во на вкладке slave и в опросе |
| Брандмауэр спрашивает про сеть | Slave слушает 0.0.0.0 (внешние подключения) | Разрешите доступ, если нужны подключения по сети; только для локальной петли можно запретить |
| «COM-порт … занять не удалось» | Порт держит другая программа (или тот же mbSCADA в другом окне) | Закройте занявший порт процесс и нажмите ⟳ Обновить |
| Мастер на линии «нет связи» с serial-слейвом | Не совпадает скорость/чётность, перепутаны A и B | Сведите `9600 8E1`-подобные настройки мастера и slave; поменяйте местами A/B на адаптере |
| Слева обрывки кадров, slave отвечает через раз | Плохой контакт на шине или второй слейв с тем же адресом | Проверьте клеммы A/B и экранирование; уберите «дубликат» устройства с линии |

## 11. Ограничения

- Симулятор доступен **только в настольном приложении** (Tauri): в браузерной демо-версии вкладка покажет подсказку «slave-симулятор доступен только в приложении».
- Один slave-инстанс на приложение: один порт, одна область памяти (четыре массива по 65 536 — holding/input/coils/discrete). Несколько «устройств» эмулируются ответами на разные unit-адреса с одной и той же картой.
- Serial-режим (v1.4) — физический RTU через USB-RS485 адаптер: один COM-порт за раз; RS-485 полудуплексный, направление передачи переключает сам адаптер. Если адаптера нет — остаются TCP-варианты кадров (MBAP и RTU over TCP).
