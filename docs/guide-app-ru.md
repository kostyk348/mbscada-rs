# 📘 Обучалка mbSCADA: от первого запуска до аварии по биту

> Актуально для **v1.8.0**. Это общий гайд по приложению: соединения, опросы, таблицы,
> правила цвета и аварии (включая именованные биты WORD-регистров), вычисляемые тэги,
> мимик-схема, журнал и архив, файлы проекта. Отдельные подробные гайды:
> [slave-симулятор](guide-slave-ru.md).

---

## 1. Что это

mbSCADA — Modbus Poll со SCADA-режимом: опрос Modbus TCP / RTU / RTU-over-TCP в живые
таблицы, байт-точный импорт настоящих `.mbp/.mbw`, 32 ветки стилевых правил на строку
с авариями, вычисляемые тэги, мимик-схема, CSV-архив — всё в одном exe. Проект — один
JSON-файл: что открыли, то и сохранили, никакой базы данных.

## 2. Первые пять минут (демо-проект)

1. Запустите приложение. Внизу в статус-строке — текущее состояние.
2. Нажмите **Демо** (или загрузите демо-проект из панели) и подтвердите замену:
   поднимется встроенный slave (`127.0.0.1:10502`), добавятся соединение, опросы,
   правила и схема.
3. Нажмите **▶ Старт** — таблицы оживут: значения «дышат», спарклайны рисуются,
   правила красят строки, аварии сыплются в панель справа.
4. Попробуйте: клик по строке таблицы — окно записи значения; ПКМ по значению —
   цикл отображения **dec → hex → bin**; вкладка **«Схема (SCADA)»** — слайдер
   и гейдж живут от тех же регистров.

Дальше — как собрать свой проект с нуля.

## 3. Соединения

Панель **«Соединения»** → добавить:

| Поле | Что вписать |
|---|---|
| Тип | `TCP` — Modbus TCP (MBAP); `RTU` — последовательная линия (COM/RS-485 через адаптер); `RTU over TCP` — RTU-кадры с CRC16 поверх TCP (так работают шлюзы). |
| Хост:порт / COM | `127.0.0.1:502` — классический порт Modbus TCP; для RTU — COM-порт и скорость (1200…115200, классика 9600), чётность `E`/`N`/`O`, 8 данных, 1 стоп-бит. |
| Slave ID | Адрес устройства 1…247 (для RTU — тот же адрес, что стоит в кадре). |
| Таймаут | Сколько ждать ответа, мс. Не отвечает — строка получает качество `bad`, опрос не подвешивает цикл. |

Кнопка **Проверить** пробует связаться сразу: так ловят опечатки в IP и скорость линии
до того, как добавлять опросы.

## 4. Опросы / адреса

Каждый опрос — одно окно Modbus Poll: одна функция, один диапазон, один тип данных.

| Поле | Смысл |
|---|---|
| Функция | `01 Coils`, `02 Discrete` — биты; `03 Holding` — регистры чтение/запись (самая ходовая); `04 Input` — регистры только для чтения. |
| Старт / Кол-во | Начальный адрес и сколько значений читать за один запрос. Адреса показываются в выбранной нотации (`40001+`, `4x0000` или с 1 — переключатель над таблицей). |
| Тип (fmt) | `u16`/`i16`/`hex16` — одно слово; `u32`/`i32`/`hex32`, `f32` (4 порядка слов), `u64`/`i64`/`f64` — 2 или 4 регистра на значение; «swap»-варианты переставляют байты/слова. Смена типа — селектором прямо на карточке таблицы, как Number Type в Modbus Poll. |
| Период | Как часто опрашивать, мс. 100–1000 — типично. |
| Шкалирование | Множитель/делитель/смещение на значение: сырые регистры → инженерные единицы (`raw·X/Y+Z`). |
| Имена и единицы | Каждой строке — своё имя и единица измерения; показываются в таблице, схеме и архиве. |

**Совет:** не дробите диапазон на много мелких опросов — один опрос 0…63 читается
одним пакетом и нагружает линию в разы меньше, чем 16 опросов по 4 регистра.

## 5. Таблицы

- **Значение** — крупно, моноширинно; **ПКМ** — dec → hex → bin для ячейки
  (hex/bin показывают сырые биты регистров независимо от fmt).
- **Спарклайн** — история значения с момента старта опроса.
- **Качество** — `ok`/`bad`/`stale`: линию порвали или устройство молчит — это видно,
  а не догадывается.
- **Клик по строке** — окно записи: типизированное значение (число, бит, float —
  по типу опроса), кнопки записи 05/06/0F/10.
- **Окно просматриваемых** — закрепите то, что реально смотрите: крупно, с цветами
  аварий и min/max за сессию. Вычисляемые тэги туда тоже можно.

## 6. Правила: цвет, текст и аварии

Панель **«Правила (цвет / авария на регистр)»**. Каждое правило — ветка на конкретную
строку (регистр). На одну строку можно повесить **до 32 веток**, работают по порядку:
первая сработавшая задаёт цвет/текст (как «правило 1 старше правила 2» в Modbus Poll).

| Условие | Смысл |
|---|---|
| значение `>` `≥` `<` `≤` `=` `≠` | Сравнение со шкалированным значением. |
| в диапазоне / вне диапазона | Окно и его отрицание (два поля: от–до). |
| бит установлен | Конкретный бит слова (см. §7). |
| всегда | Ветка «иначе» — обычно последней. |

Каждая ветка умеет: цвет текста/фона, мигание, **уровень аварии** (`info`/`warning`/
`critical` — ветка не только красит, но и поднимает аварию), сообщение (текст аварии),
и **меняющийся текст строки** («0 → Закрыт, 1 → Открыт» — подпись подменяется, пока
ветка активна).

**Аварии**: активные сыплются в панель с историй и квитированием («ACK» по одной,
«квитировать все»), критические мигают строкой в таблице. Уровень `hi/hi-hi/lo/lo-lo`
отдельно считают вычисляемые тэги-уставки.

## 7. Именованные биты WORD-регистров (v1.8)

Многие устройства статусы кладут в одно 16-битное слово: бит 3 — «работа», бит 5 —
«авария». mbSCADA позволяет назвать биты и строить правила по ним без ручного счёта.

1. В панели правил выберите **регистр** с типом `u16`/`i16` — ниже формы появится
   панель **«Биты слова (16)»**: 16 строк (старший бит сверху), у каждой:
   - **точка** — живое состояние бита прямо из опроса (зелёная = установлен);
   - **поле имени** — впишите, например, `Авария`. Имя сохраняется в проекте
     (`bitNames`), видно в форме правила, в списке правил и в таблице;
   - **▸1 / ▸0** — заполнить ветку правила по этому биту (установлен/сброшен):
     останется выбрать цвета и нажать «Добавить ветку».
2. Кнопка **«правила по всем подписанным битам»** — батч: по ветке на каждый
   именованный бит сразу (установлен, warning, янтарный фон). Уже существующие
   правила по этим битам не дублируются, лимит 32 ветки соблюдается.
3. В форме правила условие «бит установлен» теперь — **выпадающий список битов
   с именами** и состояние «установлен / сброшен» (правило по сброшенному биту
   — легально: «нет связи», «клапан закрыт»).
4. В таблице у WORD-строки с подписанными битами под именем появляется **полоска
   чипов**: чип зелёный, когда бит установлен. Наведите курсор — имя и значение.
5. В списке правил условие читается по-человечески: `бит 5 — Авария сброшен`.

## 8. Вычисляемые тэги

Панель **«Вычисляемые тэги»**: выражение над именами регистров и других тэгов.

- Операции: `+ - * /`, скобки, унарный минус.
- Функции: `min(a,b,…)` (2+ аргумента), `max(a,b,…)` (2+), `avg(a,…)` (1+),
  `abs(x)`, `sqrt(x)`, `round(x)`, `floor(x)`, `ceil(x)`, `pow(x,y)`.
- Примеры: `(T1 + T2) / 2`, `max(P1, P2, P3)`, `Q * k + b`.
- Ошибки не молчат: нечисловой результат/неизвестное имя — тэг показывает `⚠` и текст
  ошибки рядом с выражением.
- Тэги можно в виджеты на схему и в окно просматриваемых; записать их нельзя —
  их считает движок.

## 9. Схема (мимик)

Вкладка **«Схема (SCADA)»** — лёгкая мимик-панель: перетаскиваемые виджеты поверх
фона. Типы: **значение**, **гейдж**, **состояние** (красит по правилам), **слайдер**
(запись значения в регистр), **тренд**. Добавление: выбрать регистр (или вычисляемый
тэг — он только для чтения) и тип. Двойной клик — настройка виджета (подпись,
пределы гейджа, шаг слайдера). Правой кнопкой по виджету можно открыть форму правила
сразу с нужным регистром.

## 10. Журнал и архив

- **Журнал обмена** — вкладка диагностики: кадры запрос/ответ с временем отклика,
  по каждому соединению свой лог. Ищете «почему bad» — начните отсюда.
- **Журнал движка** — файл событий (старт/стоп/ошибки): панель «Журнал и архив».
- **CSV-архив** — историк: путь, интервал записи, режим «все значения» или «только
  изменившиеся». Файл открывается Excel/LibreOffice без плясок: заголовок
  `time,poll_id,poll,func,addr,name,display,quality`.

## 11. Файлы проекта и совместимость

- **Сохранить / Открыть** — проект целиком: соединения, опросы, правила (включая
  имена битов), тэги, схема, настройки журналов. Формат — JSON.
- **Импорт** — `.mbp/.mbw` Modbus Poll по одному файлу или папке: импорт байт-точный
  (round-trip `write(parse(bytes)) == bytes`), реэкспорт `.mbp ↓` на карточке опроса
  отдаёт файл, байт в байт совпадающий с исходником.
- **Адреса** — нотация показа переключается глобально; в файле хранится как в Modbus
  Poll.

## 12. OPC UA мост (`mb-opc`)

Бинарник рядом с приложением: публикует тэги проекта в OPC UA и принимает записи
клиентом обратно в Modbus (FC5/6/16).

```text
mb-opc --project project.json --listen 0.0.0.0:4840
```

- `--coalesce-gap N` — склеивать близкие диапазоны в один запрос; `--no-coalesce` —
  как в проекте.
- Адресное пространство: папка на опрос, переменная на строку, статусы соединений
  (`online`/`tx`/`errors`), вычисляемые тэги.
- Записываемые тэги — строки FC3 (holding) и FC1 (coils); FC2/FC4 — только чтение.
- Безопасность: endpoint None/anonymous — держите мост в доверенной сети.
- **Ошибки запуска понятные**: занятый порт, кривой `--listen`, нет файла проекта —
  программа печатает причину и ждёт Enter (окно консоли не схлопнется, пока не
  прочитали); в скриптах пауза пропадает сама (stdin в EOF).

## 13. Устранение неполадок

| Симптом | Где искать |
|---|---|
| Всё `bad` сразу | Соединение: адрес/порт/Slave ID; журнал обмена — уходят ли кадры вообще. |
| Одни строки `bad`, другие `ok` | Устройство ограничивает область/функцию: проверьте функцию и диапазон. |
| Значения «прыгают» странным образом | Не тот тип fmt или порядок слов (f32/i32 со swap). Попробуйте другой порядок прямо на карточке таблицы. |
| Правило не срабатывает | Ветки работают по порядку: более ранняя ветка «съедает» значение. Смотрите список правил на этой строке. |
| Порт 4840/502 занят | Другой OPC-сервер/второй экземпляр: возьмите другой порт (`--listen 0.0.0.0:4841`). |
| mb-opc вылетел | Читайте последнюю строку `error:` — с v1.8.0 причина печатается явно и окно не закрывается само. |
